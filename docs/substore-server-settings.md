## 入口与使用

新 FPK 启动后，在 Sub-Store 网页右下角点击“服务器设置 / 连接后端”，也可打开 `/_fnos/settings`。此为网页设置，不是 FPK 安装或配置向导。上游“默认后端 /path”列表不是服务器配置；它只保存浏览器连接信息。

首次管理需要从 NAS 的 `${TRIM_PKGVAR}/fnos-settings.key` 本机读取管理密钥。文件在首次启动时创建，权限 0600，由应用用户拥有；从飞牛 SSH 管理员读取，不要贴到聊天、日志、截图或 URL。应用不会把密钥打印到日志。无密钥的网页访客只能看见空表单，不能读写设置。密钥只用于本封装的服务器设置，不是上游 API 的全局登录保护。

“读取设置”后填写：

- 后端 API 路径：`/` 加 16–128 个 ASCII 字母、数字、下划线、连字符，可点按钮生成 24 字节随机路径。记录后勾选提示并保存。已有 /path 仅用于兼容迁移，不允许改回该默认值。
- 额外允许来源：精确的 `http(s)://主机[:端口]`，一行一个或英文逗号分隔，不包含路径、查询、账号密码、末尾斜杠或 *。自动内网来源和已有管理员环境变量覆盖列表仍保留。

保存时后端先校验，再以权限 0600 的临时文件原子替换 `fnos-server-settings.json`，成功后切换内存配置。可反复修改，无需重启。当前浏览器记住新路径；返回主页面后请求自动使用新前缀。保存前已在途的请求可能完成，后续旧前缀请求被拒绝。

新浏览器/设备必须在“当前浏览器连接后端”填写现有路径，再连接。路径保存在该浏览器 localStorage；不放进公开 JS、URL 查询或公开引导接口，不自动向陌生访客披露。浏览器被清理或使用无痕窗口后要重填。若另行手工添加过绝对后端地址，应更新对应条目；适配器只转换同源默认 /path 请求，不转换其他域名的后端。

## 兼容、升级与恢复

- 兼容默认单端口、前后端合并与官方 Release，不增加 npm 依赖、Docker 或 Nginx。
- 新版首次安装/旧包首次升级且无设置文件时，仍使用 /path，避免立即锁死旧客户端。请通过内网完成首次配置。
- 配置和管理密钥位于应用持久数据目录，覆盖升级保留；损坏配置或通配符 CORS 覆盖会拒绝启动，不静默退回公开默认路径。
- 忘记路径：用本机管理密钥从设置页读取；不要删除配置文件来恢复 /path。忘记密钥需要管理员从 NAS 本机读取。设置页始终要求密钥，知道旧路径不等于有权修改服务器配置。
- 启动探活使用仅回环地址且带管理密钥的 `/_fnos/health`，内部继续验证上游 env API，不依赖公开前缀。
- 网页设置仅处理本实例 API 路径和额外来源，不修改飞牛服务端口，也不修改 ESA/Lucky。
- Lucky 需要原样保留请求路径；ESA 对这些私有 API 和 `/_fnos/*` 应绕过缓存，不添加缓存所有内容规则。

## 链接、安全与边界

更改真实前缀会使旧 API 路径失效，包含旧前缀的订阅/下载链接以及其他客户端需要更新。上游独立 `/share/...` 使用原有分享令牌，路径轮换**不撤销分享令牌**，需要另外管理。绝对地址、自定义脚本构造的旧链接需手动调整；不要把新路径复制到公开脚本里。

底层 bundle 仍使用内部 /path 路由，由预加载 HTTP 网关映射外部前缀；这个内部路径只用于进程内路由，外部旧 /path 在轮换后明确 404。直接 /api、/download 也不作为旁路开放。适配器在精确来源校验通过后才移除请求 Origin，避免上游启动时捕获的静态 CORS 列表重复拒绝；这不是无条件绕过 CORS。

随机路径只降低扫描和未知访问风险，不等于登录鉴权。无 Origin 的请求不能靠 CORS 阻止；请在反代加独立访问认证。持有管理密钥的人可读取/改动 API 路径与来源，需按管理员凭据保护。已安装的环境若有不可信前端脚本或浏览器扩展，localStorage 内路径同样可能泄露。
