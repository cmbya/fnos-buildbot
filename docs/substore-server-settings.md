## 网页入口

Sub-Store 网页右下角“服务器设置 / 连接后端”，或 `/_fnos/settings`。不是安装/配置向导，也不是原有浏览器后端列表。首次在内网进入。

从 NAS 的 `${TRIM_PKGVAR}/fnos-settings.key` 本机读取首次启动生成的管理密钥（权限 0600），私下填入管理密钥框并点击“读取设置”。密钥不存浏览器、不公开显示、不打印日志，不要贴到聊天、URL、截图。密钥仅保护本封装设置，不保护上游全部 API。

## 路径明文、复制与最小长度

- “后端 API 路径”和“当前浏览器连接后端”的路径框明文显示，管理密钥仍为密码框。
- 后端 API 路径以 `/` 开头，后接 **4–128** 个 ASCII 字母、数字、下划线或连字符；开头 `/` 不计入长度，例如 `/aB12`。系统及前端保留名字（如 /path、/subs、/settings、/share、/assets）不可选。
- 点击“生成随机路径”仍默认产生 24 字节随机数编码的 48 字符长路径，生成后在框内显示，**未保存**；也可手填至少四位。
- “复制路径”“复制连接路径”：HTTPS 优先 Clipboard API；HTTP 内网或权限被拒时回退到选中文本及旧复制接口；全部失败会明确提示 Ctrl+C/长按复制，不误报成功。只复制路径，不复制管理密钥。
- 四位短路径更容易猜到，建议使用长随机路径且在反代增加鉴权。路径明文显示后截图请遮挡。

## 来源白名单及持久保存

额外允许来源填写精确 `http(s)://主机[:端口]`，一行一个或英文逗号分隔，不包含路径、查询、账号密码、末尾 `/` 或 `*`。与自动内网来源/管理员环境变量覆盖的基础列表合并。

保存前记录新路径并确认旧链接影响。后端校验后以权限 0600 的临时文件原子替换 `fnos-server-settings.json`，磁盘成功后更新内存，无需重启。失败时保持原配置；请求期间网络断开则重新读取设置确认最终状态。配置、管理密钥及短路径轮换历史均放在应用持久目录，覆盖升级保留。

旧 /path 可在首次迁移前继续使用，不允许改回默认值。切换成功后旧 API 前缀拒绝，不保留兼容别名；短前缀历史显式保存在配置文件中，重启后仍拒绝旧路径，也不允许重用已停用路径。不会把所有四位以上前端路由一并拦截，/subs、/settings 保持原用法。旧版 16+ 位配置无需重新填写。

## 当前浏览器与其他客户端

当前浏览器保存后自动记住新路径，返回首页后转换同源默认 /path 请求。公开 JS 不嵌入真实路径。其他浏览器/设备、无痕窗口或清理存储后，进入“当前浏览器连接后端”，填写现有路径并验证连接。内网 IP 和公网域名的 localStorage 独立，必须分别连接。

已手动添加绝对后端地址的条目和包含旧前缀的订阅/下载链接须手动更新；适配器不改其他域名后端。上游独立 `/share/...` 仍由分享令牌管理，路径轮换不自动撤销分享令牌。生成按钮不是凭据轮换，保存按钮才应用。

## 运维和安全边界

- 单个 Node 进程、同一监听端口、官方 Release bundle；无新增 npm 依赖、Docker/Nginx。
- 内部 bundle 仍路由 /path，外部通过网关精确映射，不对外保留旧前缀；探活走仅回环地址和管理密钥保护的 `/_fnos/health`，并检查上游 env API。
- 来源校验通过后才移除 Origin 交给上游，避免启动时静态列表重复拒绝，并非无条件绕过。
- 无配置文件首次默认 /path 兼容；损坏配置拒绝启动，绝不静默恢复 /path。忘记路径用管理密钥读取，不删除配置恢复。
- Lucky 原样保留请求路径；ESA 私有 API 和 `/_fnos/*` 应绕过缓存。新包安装后强制刷新设置页；旧安装不会因推送源码自动变化。
- 随机路径不是完整鉴权，CORS 也挡不住无 Origin 的客户端。公网使用独立认证；管理密钥按管理员凭据保护。
